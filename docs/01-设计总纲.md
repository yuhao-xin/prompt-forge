# PromptForge · 提示词锻造台 — 设计总纲

> 参赛作品：WorkBuddy「1024 造物挑战」程序员节应用创作大赛
> 定位：像 AI 产品工程师一样，通过对话式追问，把一句模糊的想法锻造成结构化、可复用、带完成标准的提示词。

## 1. 一句话价值

**新人缺的不是提示词技巧，是说不清三件事：要做成什么样（完成标准）、不给什么（红线）、给谁用（受众）。** 本工具用连续追问逼出这三件事，再按结构化模板生成提示词，最后用"体检+反馈闭环"打磨到能直接用。

## 2. 调研结论 → 设计决策（每条都有出处）

| # | 调研结论 | 出处 | 设计决策 |
|---|---|---|---|
| 1 | 提示词"黄金结构"：角色/任务/约束/输出格式/示例 | 行业共识（AI学习圈/多篇指南） | 生成模板按五件套组织，右侧卡片逐格可见 |
| 2 | LangGPT 结构化提示词，Goal 必须含 Outcome + **Done Criteria + Non-Goals** | langgptai/LangGPT（12.6k★，arXiv:2402.16929） | "完成标准"和"明确不做"设为独立槽位，是每个任务类型的**第一优先追问** |
| 3 | 优化 = 生成→测试→评分→迭代闭环；测试集/评分函数定义"更好" | mshumer/gpt-prompt-engineer（ELO 排名）、linshenkx/prompt-optimizer（39k★，评估驱动智能重写） | 反馈闭环按"差评=badcase→针对性重写"设计；"换一版"= 框架变体切换 |
| 4 | 纯前端直连、数据不经中间服务器 | prompt-optimizer 安全架构 | 零后端、零 LLM 依赖、localStorage 持久化，评委点开即用 |
| 5 | 变量替换让一条模板反复复用 | prompt-optimizer 高级模式 | 生成的提示词用 `<变量>` 标注可替换部分，导出含变量说明 |
| 6 | 路由三层：规则→向量→LLM；置信度低就追问，把不确定性变成功能 | Taskade/FastRouter/devlifted 路由指南 | 分接器 = 关键词权重打分 + 多意图确认 + 兜底框架；判定理由对用户可见 |
| 7 | 人负责判断，AI 负责产出；评测集+badcase 是质量生命线 | 用户自己的 yuhao-xin/ai-product-kit | 产品流程按迷你 AI 产品全流程设计（见下） |
| 8 | 完成度 40 分是最大评分项；能跑 > 花哨；主动砍功能 | 大赛评分标准 + 「顺手取」等参赛作品复盘 | 主链路纯前端规则引擎，不接 LLM；只做 6 个核心模块，砍掉账号/社区/云同步 |

## 3. 核心概念：一次提示词打磨 = 一个迷你 AI 产品流程

源自用户自己的 `ai-product-kit`（"让你和 AI 像一支产品团队一样工作"）：

| 阶段 | 产品团队角色 | 工具行为 | 对应 ai-product-kit 模块 |
|---|---|---|---|
| 接单 | 分接器 | 意图分类 + 置信度；多意图时让用户确认 | 需求池 / 优先级 |
| 需求澄清 | 产品经理 | 问题树追问，每次一个、可跳过、3-5 轮上限 | 需求与调研 |
| 方案生成 | 架构师 | 模板引擎填充结构化提示词 | 方案与决策（PRD） |
| 质量评测 | 测试工程师 | 五维体检 + 按分差给补强建议 | 评测体系 |
| 迭代 | badcase 驱动 | GSB 反馈 / 模块级重写 / 换框架变体 | Badcase 库 / 迭代 |
| 交付 | 交付物 | 提示词包（Markdown/JSON）+ 接入指引 | 资产库 |

## 4. 信息架构与交互

```
┌─────────────────────────────────────────────┐
│ PromptForge  [打磨新提示词] [体检已有提示词]      │  顶栏：品牌 + 模式切换
├──────────────────────┬──────────────────────┤
│                      │  ●接单 →澄清 →生成 →评测 →交付 │  右栏顶部：阶段进度
│   对话流（左侧 58%）   │  ┌──────────────────┐ │
│                      │  │ 实时提示词卡片      │ │  右栏：五件套逐格填充
│  · 分接器判定消息      │  │ # 角色           │ │      + 完成度环
│    （含判定理由）       │  │ ## 目标/完成标准   │ │
│  · 问题（每次一个）     │  │ ## 规则与约束      │ │
│    [为什么问这个 ▾]    │  │ ## 输出格式        │ │
│  · 选项按钮 / 自由输入  │  │ ## 示例           │ │
│  · [跳过这个问题]      │  └──────────────────┘ │
│                      │  [复制] [导出MD] [导出JSON] │
│  [输入框……]           │                      │
└──────────────────────┴──────────────────────┘
```

交互规则：
1. **每次只问一个问题**，选项式优先（降低新人负担），全部可跳过（用推荐默认值并在卡片上标注"待补充"）。
2. 每个问题旁有 `为什么问这个` 折叠说明（透明化，教用户提示词思维）。
3. 分接器判定后展示判定理由（命中了哪些关键词），多意图时给选项让用户确认。
4. 轮次硬上限：追问不超过 6 个问题，到顶自动进入生成。
5. 全流程 localStorage 持久化，刷新不丢。

## 5. 差异化（相对 prompt-optimizer / PromptPilot / LangGPT）

| 竞品强项 | 我们的差异位 |
|---|---|
| LLM 驱动的深度优化（39k★） | **零依赖、隐私、免费、离线**；规则完全透明可查 |
| 云端平台、功能全家桶 | **新手友好**：选项式追问 + 进度可见 + 说人话，不需要懂术语 |
| 结构化范式（LangGPT） | **完成标准驱动**：把 Done Criteria/Non-Goals 做成第一公民，这正是新人最说不出的 |
| 评估驱动的迭代 | **badcase 反馈闭环**：差评必须选原因，驱动针对性重写 |

## 6. 技术选型

- 零依赖单页应用：`index.html` + `styles.css` + `data.js`（策略库）+ `app.js`（状态机+渲染），经典 `<script>` 标签加载，`file://` 直接可跑，无构建。
- 暗色"锻造台"主题：深灰底 + 琥珀橙强调（工作台/开发者工具气质，与作品墙大量浅色作品形成区分）。
- 移动端适配（评委可能手机打开）。
- 发布为 `*.app.workbuddy.host` 链接参赛。
