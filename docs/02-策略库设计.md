# 策略库设计 — 任务分接器的心脏

> 本文件是策略库的设计规范；完整数据实现在 `../data.js`（`window.PF_DATA`）。
> 策略库是本产品真正的工作量所在（参考「四上数学全景图」的经验：花时间的是结构化，不是代码）。

## 1. 任务类型（7 个 + 1 个兜底）

| id | 名称 | 覆盖场景 | 分接关键词（权重） |
|---|---|---|---|
| writing | 内容写作 | 文章、文案、脚本、公文、小红书 | 写/文案/文章/稿/脚本/标题/公众号/软文 (2)，字数/风格/受众 (1) |
| coding | 代码开发 | 脚本、函数、调试、重构、解释代码 | 代码/脚本/函数/python/js/sql/bug/调试/报错/重构 (2)，程序/开发 (1) |
| data | 数据分析 | 清洗、统计、图表、报表、实验数据 | 数据/清洗/统计/图表/报表/excel/csv/分析 (2)，字段/指标 (1) |
| academic | 学术科研 | 论文、基金、评审、摘要、实验设计 | 论文/摘要/基金/评审/审稿/实验/参考文献/英文写作 (2)，研究/科研 (1) |
| study | 学习研究 | 讲题、复习、规划、概念解释、语言学习 | 讲/解释/复习/做题/背/学习/规划/入门/教程 (2)，概念/知识点 (1) |
| image | 绘图生成 | AI 绘画、海报、插画、logo | 画/图/海报/插画/logo/封面/壁纸/文生图 (2)，风格/构图 (1) |
| automate | 效率自动化 | 工作流、批处理、模板、整理、转换 | 自动/批量/模板/整理/转换/提取/监控/爬 (2)，流程/重复 (1) |
| general | 通用兜底 | 以上都不命中 | —（兜底框架，问题树最简） |

**分接算法**（规则版三层路由的第一层）：关键词加权求和 → 最高分 ≥3 且领先第二名 ≥2 分时判定；两名接近时列出候选让用户确认（多意图）；全部 <3 分走 general 兜底，并提示"我先按通用方式处理"。

## 2. 提示词统一骨架（LangGPT 风格 + 五件套）

```markdown
# 角色: <role>
## 目标
- 要做什么: <task>
- 完成标准: <done>        ← 第一优先追问，新人的分水岭
- 明确不做: <non_goals>   ← 第二优先追问，防范围蔓延
## 背景与输入
- 使用者/受众: <audience>
- 输入材料: <inputs>
## 步骤与方法
<steps>
## 规则与约束
<constraints>
## 输出格式
<format>
## 示例（可选）
<examples>
```

槽位（slot）即追问的落点。每个任务类型可增删章节（如 coding 多 `## 技术栈`，image 的 format 是画面描述分镜），变体只调整章节组合与措辞。

## 3. 问题树设计五原则

1. **每个问题必须填一个槽位**——不问废话；问题与卡片槽位一一对应，用户看得见自己的答案在长成提示词。
2. **优先级排序：完成标准 > 明确不做 > 受众 > 输入 > 其余**——把新人最说不清但最重要的放最前（LangGPT 的 Done Criteria 洞察）。
3. **选项式优先，全部可跳过**——选择降低认知负担；跳过后用推荐默认值，卡片上标灰字"待补充"。
4. **每个问题带"为什么问这个"**——透明化即教育，用户下次自己会写提示词（产品的第二价值）。
5. **轮次硬上限 6**——到顶停止追问，自动生成；不问烦用户（PromptPerfect 用 3-5 轮，我们略放宽）。

## 4. 框架变体（"换一版"的规则实现）

每个任务类型 2-3 个变体，切换时保留全部已填槽位、只改模板组合：

- **标准版**：完整骨架，适合大多数场景
- **严谨版**：追加"自检清单/反例约束"章节，约束升级为禁止项列表（对应 prompt-optimizer 的"硬核评审"demo 思路）
- **简洁版**：删步骤与示例，只留角色/目标/格式，适合简单任务或小模型

## 5. 五维体检（对已有提示词，规则检测 0-2 分/维，满分 10）

| 维度 | 2 分标准 | 检测规则（启发式） |
|---|---|---|
| 角色 | 有具体身份+专长+年限/领域 | 存在 `# 角色`/`你是` 且角色词 ≥2 个限定词 |
| 任务 | 含动作+对象+**完成标准** | 存在"要做什么/任务"且含"标准/要求/使得/确保"类词 |
| 约束 | 有禁止项/边界 | 含"不要/禁止/不得/避免/仅"类词 ≥1 |
| 格式 | 输出结构具体 | 含"格式/表格/Markdown/JSON/字数/分点"类词 |
| 示例 | 有 1 个以上示例 | 含"示例/例如/比如/样例"或代码块/引文块 |

低分维度 → 输出该维度的**补强建议文案**（预写模板，按维度给 2-3 条具体改法），支持"按建议补强"一键把建议转成追问补答。

## 6. 反馈闭环（badcase 驱动）

- **GSB**：`好用` / `一般` / `不行`。
- `一般`/`不行` → **必选原因**（对应五维：角色不对/任务不清/约束不够/格式不对/缺示例/其他）→ 进入该模块的针对性重写（重写=用该模块的预写优化策略重新生成该节）。
- **换一版** → 变体切换。
- 全部反馈写入 localStorage 的"打磨记录"（可回看本次改了哪些、为什么）。

## 7. 导出（第二步：应用到项目）

- **Markdown 提示词包**：主提示词 + 变量说明表 + 三段接入指引（WorkBuddy 新对话直接粘贴 / Claude Projects 系统提示词 / API `system` 字段）。
- **JSON**：结构化 `{role, goal, done, non_goals, audience, inputs, steps, constraints, format, examples, variables[]}`，供开发者集成。
- **复制**：一键复制主提示词，`<变量>` 保留原样。

- [ ] 全跳过（一路点"跳过"）仍能生成完整提示词（默认值兜底）
- [ ] 空输入/超长输入/纯符号输入不崩溃
- [ ] 追问第 6 问后强制进入生成（死循环防护）

- [ ] 手机宽度（375px）下布局不破
