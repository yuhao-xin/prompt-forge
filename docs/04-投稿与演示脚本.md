### 作品简介（可直接复制）

> **PromptForge · 提示词锻造台**
>
> 用 AI 最大的障碍不是不会写提示词，而是说不清三件事：要做成什么样、不给什么、给谁用。
> PromptForge 像一位 AI 产品工程师，通过对话式追问逼出这三件事，按结构化模板现场生成提示词，
> 再逼你回答最后一问——"你打算拿什么真实输入去试它？"——把"能用"从口号变成可判定。
>
> **核心机制**：① 任务分接器（关键词权重打分 + 多意图确认 + **判定理由可见**）
> ② 追问引擎（每次一个、可跳过、可回退、每问带"为什么问这个"）
> ③ 实时提示词卡片（逐格填充，黑盒变白盒）
> ④ 五维体检（含命中证据）⑤ GSB 反馈闭环（**按模块重写**而非笼统重生成）
> ⑥ 就地改写（改完自动重新体检）⑦ 经验库（跨会话沉淀，越用越懂你）
>
> **技术特点**：零依赖单页应用、零后端、离线可跑、数据不出浏览器。

## 三、演示脚本（评委视角 · 90 秒）

评委平均只给一个作品 30–60 秒，所以**前 10 秒必须让他看到复杂度上限**。

| 时间 | 操作 | 评委会看到什么 |
|---|---|---|
| 0–10s | 打开链接，点右侧**「读一篇 Nature 论文，判断方法是否可靠」** | 立刻进入追问，不是玩具级需求 |
| 10–30s | 连点 3–4 个选项 | 右侧卡片**逐格长出内容**，进度条推进 |
| 30–50s | 答完最后一问 | 提示词成型，自动跑**五维自检**并给出弱项 |
| 50–70s | 点卡片任意一段改一个字 | 就地编辑生效，**自动重新体检**（分数变化） |
| 70–90s | 点「导出 MD」 | 完整提示词包：五件套 + 接入指引 + **验收用例** |

### 演示时的三句话

1. **"它不生成答案，它生成能反复用的提示词资产。"**
2. **"每个追问都能告诉你为什么问——这是把提示词思维教给你，不是替你想。"**
3. **"最后一问很关键：不先想好拿什么去试，就永远不知道它到底行不行。"**

## 六、GitHub 开源发布（手动）

自动化建仓被 GitHub 侧拒绝（连接器无建仓权限，403），按下面步骤手动执行即可，**约 3 分钟**。

### 步骤 1 · 建空仓库

1. 打开 <https://github.com/new>
2. `Repository name` 填 **`prompt-forge`**
3. `Description` 填：
   ```
   提示词锻造台 · 像 AI 产品工程师一样，通过对话式追问把模糊想法锻造成带验收标准的提示词资产（零依赖单页应用）
   ```
4. 选 **Public**
5. **不要**勾选 "Add a README file" / ".gitignore" / "License"（我们已有 README，避免冲突）
6. 点 **Create repository**

### 步骤 2 · 推送代码

仓库建好后，GitHub 会显示推送命令。在本地执行：

```bash
cd "D:/Software/workbuddyfiles/2026-10-25-20-59-52/prompt-forge"

git init
git add .
git commit -m "feat: PromptForge 提示词锻造台 — 任务分接器 + 追问式提示词锻造"

git branch -M main
git remote add origin https://github.com/yuhao-xin/prompt-forge.git
git push -u origin main
```

> 如果已有 `origin`，先 `git remote remove origin` 再执行上面第 5 行。
> 若 GitHub 启用了 2FA，push 时用 **Personal Access Token** 代替密码。

### 步骤 3 · 配置仓库信息（提升"漂亮度"）
