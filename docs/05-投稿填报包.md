## 二、作品介绍（整段复制）

```
用 AI 最大的障碍不是不会写提示词，而是说不清三件事：要做成什么样、不给什么、给谁用。PromptForge 提示词锻造台就是为这件事做的：你只说一句需求，它像一位 AI 产品工程师那样连续追问，把这三件事逼出来，再按结构化模板现场锻出一条能直接用的提示词。

它和"提示词生成器"有三点不同。第一，每个追问都告诉你"为什么问这个"，把提示词思维教给你，而不是替你想。第二，右侧的实时提示词卡片会跟着你的回答一格一格长出来，黑盒变白盒，你能看见提示词是怎么被锻出来的。第三，它会逼你回答最后一问——"你打算拿什么真实输入去试它？"——没有验收标准的提示词，再漂亮也只是口号。

核心机制：① 任务分接器（关键词权重打分，多意图时列出候选让你确认，判定理由全程可见）② 追问引擎（每次一个、可跳过、可回退、轮次上限，覆盖 8 类任务并带通用兜底）③ 实时提示词卡片（逐格填充）④ 五维体检（角色/任务/约束/格式/示例，附命中证据）⑤ GSB 反馈闭环（差评必选原因，按模块针对性重写，而非笼统重新生成）⑥ 产物就地改写（改完自动重新体检）⑦ 经验库（跨会话沉淀你的受众、风格、常用约束，越用越懂你，数据只存本地）。

技术上是零依赖单页应用：无后端、无密钥、离线可跑、数据不出浏览器。评委点开链接即可完整体验，无需登录或配置。

适合谁：需要反复用 AI 做复杂任务的人（读论文、写代码、拆项目计划），尤其是说不清需求的新手——它把"提问"这件事本身做成了可以被引导的流程。
```

## 五、为什么自动化投稿没走通（记录）

活动页 `submitWork()` 的硬性约束：

1. **`getCurrentUid()` 必须与填写的 UserID 一致** → 必须在已登录 WorkBuddy 的会话里提交，外部浏览器无登录态会直接报"请登录 WorkBuddy 后再投稿"。
2. 页面在外部 Chromium 中渲染为空白（依赖 WorkBuddy 客户端上下文），无法直接操作表单。
3. 截图通过 `window.__SMART_PAGE__.database.uploadFile` 上传 CDN，也依赖该运行时。

**结论**：最后一步必须由你在已登录的 WorkBuddy 里点提交（或用我开的有头窗口登录后由我代填）。其余全部已备好。
